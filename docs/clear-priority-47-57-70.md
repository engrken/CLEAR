# CLEAR Priority #47 / #57 / #70 combined patch

**QR / certificate security (#57).** The authorized officer web clearance view renders a QR entirely inside CLEAR via a vendored, MIT-licensed local QR encoder (Kazuhiko Arase). Newly issued web/mobile officer verification links contain only a 7-day AES-256-GCM encrypted, random-nonce bearer token with separate key derivation from the server secret. Claims bind tenant, Student database UUID and school number, academic year and term. QR verifier checks the trusted token, current active tenant period, canonical student identity, active enrollment, and authoritative live obligations before showing just valid/invalid. A later recorded fine/VOID/debt or enrollment change invalidates positive verification. Public page does not show names, student IDs, financial balances, or third-party QR HTTP calls. Referrer policy, cache control and no-index apply. Existing HMAC legacy links continue to work; **this does not revoke previously issued links individually**. Owner acceptance should include a real phone camera QR scan on Preview with synthetic enrolled/cleared and subsequently-held cases. Certificate links are transferable status proofs, not student login credentials.

**Student email (#47).** The authorized Students roster displays the **count of records missing a usable email** and links its existing Edit Student workflow to an identity-checked administrative process. No automatic email assignment, school-ID-only lookup, or OTP bypass. Students lacking an existing email still cannot authenticate without a verified roster update; administrators are responsible for correctly confirming the new address. Clear consent and school process needed before changing live data.

**Performance (#70).** Receipt History first narrows selective `q` candidate official receipt numbers in tenant/AY/term-scoped SQL, then fetches ALL allocation lines for each receipt before grouping/filter/pagination. Broad searches fall back to the original full read to protect legacy cross-period, suffix and inconsistent-OR behavior. No new index DDL or numeric modifications. Benchmark representative staging and capture p50/p95 before claiming an end-user speedup.

**Parity:** Shared mobile officer API issues the same opaque verification URL; student-private mobile API continues to return no QR and requires OTP. The published v1.2.2 Android binary is unchanged. No native financial transactions enabled. Per #64, next Android UI build may add a native first-party QR view after Play device QA.

**Release gates:** one PR, consolidated 192-test gate + new QR/crypto/performance tests, isolated OTP/runtime and financial actions tests, Vercel Preview/Production verification, real camera QR scan, and role-separated UAT. Do not claim issue #57 completely closed without camera-scanned verification and proper revocation/lifetime approval. Do not claim #70 complete without measured p95.
